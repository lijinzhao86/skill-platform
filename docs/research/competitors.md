# skill-platform 竞品分析

> 调研日期：2026-09-20 · 数据来自公开报道与官方文档，标注了时点
> 用途：为 [`blueprint.md`](../target/blueprint.md) 的**定位与差异化**提供论据底稿
> 结论先行：**业内四层里，分发、计价、信任三层都有人做；「分层」门控是空的**（整包级门控存在——Agensi 就是；按内容层级分档的没有）。那是 skill-platform 唯一的位置。

---

## 一、怎么读这份分析：四层拆解法

把所有玩家放在同一套坐标系里比较，比按公司罗列清楚得多。技能从产出到收费要经过四层：

| 层 | 回答的问题 | 空了这个会怎样 |
|---|---|---|
| **① 分发层（Hub）** | 技能从哪里被发现、安装、更新 | 没人找得到，等于不存在 |
| **② 计价层（Meter）** | 卖的是什么单位 | 收不了钱 |
| **③ 门控层（Gate）** | **未付费的内容能不能被拿到** | 收费只是君子协定 |
| **④ 信任层（Trust）** | 质量与安全由谁担保 | 用户不敢装 |

**关键洞察在于 ③ 与 ② 的耦合**：如果内容一旦分发就全量落到用户手里（所有现有 Hub 的默认假设），那么无论计价层设计得多精细，收费都拦不住绕过。反过来，**要做分层计价，前置条件是分层分发**。

这就是为什么**分层**门控是空的——不是没人想到，是**它要求推翻现有 Hub 的基础假设「装上就是你的」**。

## 二、三条生态线（不是一个市场）

SKILL.md 是共同格式，但分发入口分属三个阵营。**不认清这一点，会误判竞品。**

| 线 | 标准/格式 | 核心 Hub | 谁在服务它 |
|---|---|---|---|
| **OpenClaw 线** | SKILL.md（OpenClaw 采用） | ClawHub | 腾讯 SkillHub、火山引擎 ArkClaw |
| **Claude Skills 线** | SKILL.md（Anthropic 开放标准，agentskills.io） | 无单一官方市场，多个第三方 | Agensi、免费目录群 |
| **自建 Hub 线** | SKILL.md / MCP | 魔搭 Skills 中心、Dify Marketplace | 阿里、Dify |

**对 skill-platform 的含义**：skill-platform 交付的是「目录树 + SKILL.md」，这是三条线共用的装载格式，**天然跨线**。这是一个被低估的优势——竞品大多绑定单一生态（腾讯绑 OpenClaw、Agensi 主打 Claude Code 系），而 skill-platform 不需要选边。

## 生态线一：OpenClaw / ClawHub

### 1. ClawHub —— OpenClaw 官方市场

| 项 | 内容 |
|---|---|
| 定位 | OpenClaw 的公共技能注册表与市场，自称 **"npm for AI agents"** |
| 上线 | 与 OpenClaw 同期（**2025 末 – 2026 初**）。所引来源只写"与 OpenClaw 同期创建"，**没有给出具体日期**（clawhub.ai，GitHub: openclaw/clawhub） |
| 所有权 | OpenClaw 开源社区 / OpenClaw Foundation |
| 技能格式 | Markdown `SKILL.md` 目录 + 辅助文件（**不是 MCP plugin**——所引来源没有任何"MCP 打包"的描述） |
| 规模 | 2025-11：127 个 → 2026-03：15,000+；另有来源称约 2 万。**时点数字互相矛盾**：一份记录停在 2026-02-28 的 13,729，而一篇 arXiv 注册表爬取记 2026-06 约 6.5 万、2026-07 约 6.8 万。**故不引用单一数字** |
| 发现 | 向量语义搜索 + slug 前缀匹配；11 大类目；质量评分与使用指标。（所引 wiki 只证实检索"由 embedding 驱动"，**未公布具体模型与向量库**） |
| 安装 | `clawhub install <slug>` → 落到 `~/.openclaw/skills/` |
| 审核 | 开放发布、**无事前审核**；有事后举报机制，但**隐藏需管理员决定**——现行 `specs/security-moderation.md` 明确"举报不会自动改变可见性"（"Reports never change skill visibility or installability automatically"）。发布者需 GitHub 账号年龄 **≥ 14 天**。⚠️ 该 spec 的**旧版本**曾写"独立举报超过 3 个自动隐藏"，现行版本已无此规则——引用前先确认版本。（原稿引的英文 "indexes everything without formal review" 在所引来源里找不到） |
| 附带 | 另有 SOUL.md 注册表（onlycrabs.ai）分享系统设定与角色 lore |

**四层评估**：① 有（官方，且是生态入口）② **无**（纯免费）③ **无** ④ **无**（明确不做审核，把判断推给用户）

**值得注意**：官方文档建议用户自行查 VirusTotal 报告、评估发布者 GitHub 账号信誉、遵循最小权限。这是把安全责任完全下推给用户的做法——也正是 Agensi 和腾讯 SkillHub 的切入点。

### 2. 腾讯 SkillHub + SkillPay —— 国内配套 + 首个中文付费体系

**SkillHub（2026-03-11 上线，skillhub.cn）**

定位：**基于 OpenClaw 官方开源生态打造的本土化配套服务平台**，兼容官方全量技能生态，**不改动官方开源内容**。即：镜像 + 精选 + 中文社区，不是原创市场。

| 项 | 内容 |
|---|---|
| 起点 | 聚合官方社区 13,000+ Skills（2026-03） |
| 增长 | 3.5 万（2026-04-28）→ **7.8 万（2026-07-17）** |
| 流量 | 月下载 **1700 万+**，累计 **6000 万+**；称国内最大 Skill 创建与分发平台 |
| 解决什么 | 官方 ClawHub 部署海外 → 国内下载卡顿、上万技能无从筛选、中文搜索差、缺中文社区 |
| 三大功能 | 国内高速镜像节点 · 精选 Top 50 榜单（官方认证+加速+安全审计）· 开放中文社区 |
| 兼容 | OpenClaw、WorkBuddy、QClaw、AI Coding 场景；可对接腾讯云 Lighthouse、Mac 本地 |
| 工具链 | `skillhub-cli`（npm）· 官网图形化发布（含 **AI 辅助生成**技能名/描述/分类/标签/指令）· 发布流程 = 提交审核 → 平台安全检测 → 自动上架 |
| 战略角色 | 是 Marvis、WorkBuddy 等腾讯系 Agent 的**技能来源** |

**TRACE 评测体系（腾讯首发）** —— 这是 SkillHub 真正自建的部分

| 维度 | 核心问题 | 评测内容 |
|---|---|---|
| **T** Trust | 能不能放心用 | 安全检测、最小权限、敏感信息保护、国内可用性、中文支持。**红线维度：触碰安全红线直接淘汰，不看其他维度得分** |
| **R** Reliability | 能不能稳定用 | 稳定运行、一致结果、边界输入、异常反馈 |
| **A** Adaptability | 该不该在这个场景用 | 场景匹配度、触发条件清晰度、能力边界、输入输出规范性 |
| **C** Convention | 能不能被理解维护 | **渐进式披露**、文档结构、限制说明、示例充分性 |
| **E** Effectiveness | 是否真正解决问题 | 结果正确性、输出完整性、可直接使用性、减少返工率。**主客观结合，用客观对照实验测结果增益** |

> 注意 **C 维度把"渐进式披露"列为规范性考察项**——官方生态已经把它当作**质量指标**。skill-platform 要把它当作**计价单元**。同一机制，两种用法，这是 skill-platform 与腾讯最本质的分歧点。

**SkillPay（2026-07-16 上线）**

| 项 | 内容 |
|---|---|
| 计费单元 | **按调用量结算** |
| 支付通道 | 微信支付 **AI 专属卡** |
| 三方分工 | SkillHub（来源认证 / 内容完整性校验 / 可信调用入口）+ 微信支付（底层支付体系与安全保障）+ 商家（定价权与收款权） |
| 商家三步 | ① 企业认证 + 绑定微信支付账户 → ② 上传 skill、设置价格与计费模式（**"简易改造即可把已有 Skill 封装成 Pay Skill"**）→ ③ 上架发布，即获面向**所有接入 Agent** 的收费能力 |
| 用户体验 | 在 WorkBuddy / QClaw 中经 SkillHub CLI 安装 Pay Skill，**对话内直接弹支付授权**，不跳出端外 |
| 首批行业 | 餐饮零售、AIGC 内容制作、在线旅游、金融数据服务 |
| 标杆案例 | 腾讯视频 **WorkRally**（工业级 AI 影视/漫剧创作）发布生成图片/视频的 Pay Skill |

**四层评估**：① 有（镜像+精选+社区）② 有（按调用量）③ **无** ④ 有（TRACE 五维 + 安全扫描，平台背书）

**腾讯的真实位置**：**全链路垂直一体，但 Hub 是寄生在别人生态上的。** Agent 端（WorkBuddy / QClaw，QClaw 上线 10 天超百万用户）→ 分发（SkillHub）→ 支付（SkillPay）→ 模型（混元 Hy3，OpenRouter 调用量总榜第一）→ 云（Lighthouse / TokenHub）→ 安全（AI Agent 安全中心）。

**但它做的付费技能与 skill-platform 不是同一件事**：WorkRally 这类是**把企业 API 服务包装成 skill 按调用收费**，本质是 API 计费换了个壳，不是内容资产的分层授权。这也解释了央广网观察到的现象——"企业上架的 Skill 多是母业务的功能模块，调用量再高也不单独收费"。

## 生态线二：Claude Skills / agentskills.io

### 4. Agensi —— 最接近 skill-platform 的付费市场

| 项 | 内容 |
|---|---|
| 定位 | **"The trust and distribution layer for AI agent skills"** ——安全扫描、跨 agent、创作者变现 |
| 计费单元 | **整包买断** |
| 分成 | **创作者留 70%**（售卖页："Keep 70% of net revenue"、"one all-inclusive 30% platform fee"）。创始人另有说法：直销 80% 再减 $0.50/单、MCP 订阅抽 70%。**两个口径都公开发布过，别只引一个** |
| 跨 agent | Claude Code、Cursor、Codex CLI、Gemini CLI、OpenClaw 等 **20+ 种** |
| 差异化 | 每条 skill **全量安全扫描**；提供 **MCP server** 让 agent 原生发现（"your agent connects and suggests relevant skills mid-conversation"） |
| 常见价位 | 一次性 **$19 / $29 / $49 / $99**；订阅 **$19–49/月**（据其售卖页）。原稿的 $3–5 只在二手来源里出现 |
| 起点动机 | "800,000+ skills scattered across GitHub — no curation, no security, and no way for creators to earn" |
| 团队 | 单人创始人，Lovable + Supabase |
| 安装 | 付款后才放行的**带指纹 ZIP**（买家 UUID 打戳、按需生成），装到 `~/.claude/skills/` 或经 MCP 直接进 agent。原稿的 `curl … \| tar xz -C ~/.openclaw/skills/` 与实际流程不符 |

**四层评估**：① 有 ② 有（整包）③ **有**（整包级：未付费拿不到付费文件；但**没有层内分级**）④ 有（全量安全扫描 + 精选）

**为什么 Agensi 是最该盯的竞品**：它是唯一在"创作者变现 + 信任"这条路上跑通早期形态的玩家，且**跨 agent**——与 skill-platform 的边界最接近。但它的计费单元是**整包买断**，正是 skill-platform 要解决的"买家在最不确定时做最大决策"的问题。**它一次性 $19–99 的价位反而放大了这个问题**：买家要在最不确定的时候先付 $29 赌一把。（原稿据 $3–5 推出"复制不如再买"——价位订正后该推论不成立，结论方向相反。）

| 战略意义 | **支付宝支付集成 Skill 的首发地**（2026-03-31） |
| 内容运营 | 有 1,000+ 科研 skill（从中严选 18 个）；FlagOS Skills（异构 AI 芯片）；端侧本地 AI 文件治理 Skill 等 |
| 第三方支付 | 拉卡拉 MOSS 支付 Skill 上架 |
| 安装 | `npx skills add <url>` / `modelscope skills add` / `curl install.sh` |

**四层评估**：① 有（依托模型社区流量）② **无**（技能免费，支付能力由第三方 Skill 提供）③ **无** ④ 部分（社区运营策展，无统一评测标准）

**关键观察**：魔搭验证了一个重要模式——**支付能力本身可以是一个 Skill**。支付宝把自己的支付能力做成 Skill 上架到别人的 hub。这反向证明了：**支付宝不打算做 hub，它要做的是被所有 hub 集成的那一层。**

## 支付层（横向，非 Hub）

### 7. 支付宝 AI 支付开放平台 —— 最该合作的对手

**定位**（官方原文）：面向 **AI 应用、AI 创作者、Skill/API 服务商、模型与云服务商，以及 Agent 和智能终端生态**，提供覆盖应用收款、Skill 变现、API 按量计费、模型 Token 采购、持续订阅和 Agent 代理支付的支付解决方案。**底层复用支付宝成熟的收单、风控与资金安全体系。**

**产品矩阵**

| 产品 | 面向 | 计费单元 |
|---|---|---|
| **Vibe Pay**（AI 应用收款） | AI 创建的网页/移动应用 | **一次性买断、次数包、积分包、时长包** |
| **Skill Pay**（AI 技能收款） | Skill 服务商 | 嵌入 Skill 的调用与交付流程 |
| **Machine Pay**（AI 按量付费） | API、MCP、Skill、数字内容、算力资源 | 按调用或用量 |
| **Token Pay**（AI 连续订阅） | AI 应用的订阅管理 | 周期计费、套餐、自动续费、席位 |
| 另有 | AI 付、AI 打赏、支付 MCP Server、支付集成 Skill | — |

**Vibe Pay 的两种模式**（对本产品最有参考价值）：

- **基础收款能力**：提供支付、订单查询、退款等**原子能力**，创作者自行设计付款流程、订单与权益管理。
- **智能收款套件**：**通过合作平台接入**，下单支付、订单管理、权益管理开箱即用，创作者只负责设计付费触发条件与支付成功后的功能放行。

**时间线**

- **2026-03-31**：发布国内首个「支付集成 Skill」（`@alipay/alipay-payment-integration`），用 **SKILL.md 标准**、兼容 Claude Code，**首发上线魔搭 Skills 中心**。
- **2026-04-28**：上线「支付宝 AI 收」，按调用即时收款，三步接入（入驻签约 / 创建应用 / 安装 SDK）；个人开发者 **0 费率至 2026-12-31**。
- **兼容性**：已支持 **95% 通用智能体框架**——千问、JVS Claw、Claude Code、Hermes、TRAE SOLO、Qoder、扣子等。

**官方文档里三句极有价值的话**

1. 「**智能收款套件通过合作平台接入**」→ 主动把 Hub 的角色让出去。
2. 「面向 **Skill 开发者的变现需求则应另行评估 Skill Pay**」→ 纯支付/API 视角，不谈分发与内容。
3. 「**不适用场景**：如果我们还没有可交付的付费权益，不建议急着接入支付。更适的做法是**先提供免费试用，验证服务价值**。」→ **支付宝把"先免费试用"当作一句建议给出，但没有给机制。skill-platform 的 L1/L2 免费 + L3 付费，正是把这句建议产品化了。**

**四层评估**：① **无（明确不做）** ② 有（但只是原语，需接入方自行组合）③ **无** ④ 无（交给合作平台）

### 8. 海外支付协议 —— 全是按次

| 玩家 | 计费单元 | 特征 |
|---|---|---|
| **x402**（Coinbase 系） | 按次（USDC 链上） | 加密原生，适合机器对机器 |
| **Cloudflare Agents SDK** | 按次 | `paidTool` drop-in 替代 `tool`，`withX402` 包一层即可；**支持同一 server 混合免费与付费 tool** |
| **Stripe MPP** | 按 session | 法币 |
| **MCPize / Apify / MCPX** | 按次 / 订阅 | MCPX 定位"发现、安装、发布 MCP server 并获得报酬" |
| **MarketNow** | 按次 | 索引 8,560 个 MCP skills |
| **AgentPay VN** | 按次 | `pip install agentpay-vn`，MCP server 收费 |

**公开的四种模型**：per-call、subscription、freemium、outcome-based。

**业界自己承认的痛点**（对 skill-platform 极有价值的一段公开论述）：

> per-call micro-pricing（$0.01 × 50 calls/day ≈ ~$15/mo）**is barely worth metering**，and once you charge real money the hard part is the meter, per-tool rates, **idempotent dedup**, per-agent caps, and aggregating sub-cent calls into one invoice.

以及另一句：

> Thousands of MCP servers shipped in the last year, and **almost all of them are free, which means almost none of them are a business.**

**四层评估**：① 无 ② 有（按次为主）③ **无** ④ 无

**这就是 skill-platform"不按次计费"的直接依据**：微支付的计费成本会吃掉收入，且用户在执行前不知道要花多少。

## 五、为什么**分层**门控是空的

先厘清一点：**「门控」本身不是空白**——Agensi 的整包买断就是整包级门控，未付费拿不到付费文件。空的是**层内分级**：没有任何一家按内容层级分档授权。

这不是没人想到，是**三条结构性原因**：

**1. Hub 的基础假设与之冲突。** 所有现有 Hub 的默认心智是「装上就是你的」——技能装到 `~/.openclaw/skills/` 后就是一个本地文件夹。要做分层门控，必须推翻这个假设，改成「按需向服务端取件」。这不是加一个功能，是换一套分发架构。

**2. 大厂的商业模式与之不匹配。** 腾讯 SkillHub 上架的付费技能多是企业自家业务模块（WorkRally 生成图片/视频），它们计的是**调用 API 的成本**，不是**内容资产的价值**。对这类供给，按调用量计费是正确的；分层授权反而是多余的复杂度。

**3. 支付方主动让出了这一层。** 支付宝明确只做支付原语，且「智能收款套件通过合作平台接入」——它把设计付费触发条件与功能放行的责任**留给了平台方**。也就是说，**支付宝已经把"门控该由谁做"这个问题交了出来，但还没有人接。**

## 六、对 skill-platform 的含义

### 1. 差异化必须精确表述

**不是**「节点买断 + 钱包」——支付宝 Vibe Pay 已支持一次性买断、次数包、积分包、时长包，腾讯支持按调用量。**计费原语是现成的，skill-platform 在这里没有创新。**

**是**这两件事：

- **怎么切分节点**（把官方渐进披露机制作为切分依据，与 agent 加载行为严格对应）
- **怎么门控分发**（未解锁不下发——这是让分层计价真正成立的地基）

一句话：**别人在解决"怎么收钱"，skill-platform 在解决"卖的是什么单位，以及怎么保证没付钱就拿不到"。**

### 2. 支付层是对手也是通路

支付宝是**合作方不是竞品**——它明确不做 Hub，且把门控留给了平台方。skill-platform 的支付通道将来直接接微信/支付宝即可，**不自建**。这一点应写进产品边界。

### 3. 跨三线是被低估的优势

腾讯绑 OpenClaw、Agensi 主跨 Claude Code 系、魔搭绑自家模型社区。skill-platform 走服务端权威 + 网关 skill + API（[ADR 0001](../decisions/0001-server-authoritative.md)），**任何能发 HTTP 请求的 agent 都能用**——跨线能力来自交付形态本身，不来自某个模块。这是定位里应该显式声明的能力。（原稿把它归因于 materializer；该模块已删除。）

### 4. 两个必须正面回应的竞争动作

| 风险 | 说明 | 应对 |
|---|---|---|
| **腾讯把 TRACE 的 C 维度升级为计价** | 腾讯已把"渐进式披露"列为质量考察项（C 维度）。它离"按披露层计价"只差一步——**认知上是通的，缺的是分发架构改造**。一旦它做，分发优势巨大 | 抢时间窗；同时积累"卡在哪一层"的作者侧数据，形成迁移成本 |
| **Agensi 加入分层** | Agensi 已跨 20+ agent、已有付费与信任层，只差门控。单人团队，转向可能比腾讯快 | 同上；且 skill-platform 有 Agensi 没有的组织/个人双层权益（企业内部场景） |

**护城河不在技术，在作者侧的数据与工作流粘性。** 越早开始积累「哪一层被撞、解锁率多少」，作者越难迁移。

### 5. 一个可直接用的话术

支付宝官方文档说：「如果不确定，**先提供免费试用，验证服务价值**」——它给了建议，没给机制。

**skill-platform 就是这句话的产品化：L1/L2 免费即试用，L3 按节点解锁即验证后的付费。**
