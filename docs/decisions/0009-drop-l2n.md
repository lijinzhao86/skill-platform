# ADR 0009 · 砍掉 `l2#n`，付费边界只落在层与层之间

- **状态**：已采纳
- **日期**：2026-09-26
- **影响**：[`target/design.md`](../target/design.md) 的节点模型（该文档仍写着 `l2#n`，尚未同步）

## 背景

产品设计里有一个机制：在 `SKILL.md` 正文里放细切标记，把正文切成若干段，**每段单独定价**（`l2#1`、`l2#2`…）。它的动机是给"纯正文型" skill 一个收费点——因为默认策略是 L3（文件）付费，而实测 30 个真实 skill 里有 9 个**根本没有 L3 文件**。

## 决定

**不做 `l2#n`。** 付费（将来若做）**只落在标准已有的层与层之间**：L1 / L2 免费，L3 付费。

## 理由

- **它不是标准里的东西。** Agent Skills 规范只有三层（metadata / instructions / resources），且明确说正文是**整个文件**一次加载的——不存在正文内子段落寻址的概念。客户端的原生渐进加载也不会"只读第 n 段"。
- **标准对"想少加载正文"已经给了答案**：**把详细内容移到 `references/`**（即 L3）。规范原文建议正文保持 500 行以内、把详细材料外移。也就是说，作者想让深度内容成为付费点，标准路径本来就是把它们拆成独立文件。
- **实现成本差异巨大。** 移进 `references/` 需要平台写**零**机制，客户端的原生分层加载直接生效；`l2#n` 需要自定义标记语法 + 服务端重装正文 + 解锁后重新下发。
- **完整性上有具体劣势。** 标准要求 approval 绑定完整的 URI+digest 集合，文件增删改即吊销。`references/` 是独立文件，作者改付费文件才吊销；而 `l2#n` 是同一个文件——**作者改任何一段免费正文，都会连带吊销买家对付费段的批准**，造成无谓的重新批准。
- **业界无人这么做。** 变现只有整包买断（Agensi、ClawHub）与按次计费（腾讯 SkillPay、x402、Cloudflare `paidTool`、Stripe MPP）两类，**没有一家做"按内容层级计费"**。

## 后果

- **纯正文型 skill 若要收费，必须按标准的建议把深度内容拆成 `references/`。** 这样一来，费用点是标准认可的 L3，而不是平台自定义的段落。这是**作者侧的写作规范**，平台可以在上传时给分级提示，但不应强制。
- 平台少了一整套机制：标记解析、正文重装、解锁后重新下发。
- `target/design.md` 仍有 4 处按 `l2#n` 描述，**需要同步修订**：第 0 章（核心机制表与设计边界）、第 5 章概念模型的 `kind` 枚举、附录「已锁定的产品决策」。另外**第 6 章 Q1「细切标记的具体语法」被本 ADR 直接关闭**，不必再定语法。第 0 章「节点必须与官方加载层严格对应」一句也需调整表述——L1/L3 对应标准层，`l2#n` 正是不对应的那个。**逐条清单（含行号）见 [`target/README.md`](../target/README.md)。**
- 将来若重启付费，接入点收窄为：在 `version_file` 上挂价格、在四个读接口加权益判定，不需要碰正文渲染。
